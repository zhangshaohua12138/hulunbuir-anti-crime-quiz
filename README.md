# 呼伦贝尔扫黑除恶有奖答题系统

依据 V1.1 需求实现的公众号 H5 与运营管理系统。包含参与者七页、管理后台、SQLite 数据库、Excel 导入导出、微信 OAuth/关注校验/JS-SDK 签名、现金红包直连及支付网关适配。

## 在当前 Windows 电脑启动

运行 `start-demo.ps1`，浏览器打开 `http://127.0.0.1:8080`。管理后台 `http://127.0.0.1:8080/#admin`，演示账号 `admin`，密码 `demo-admin-2026`。

启动脚本优先使用当前 DeepSeek Harness 已配置的 Python。其他机器安装 Python 3.11+ 后执行：

```powershell
python -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements.txt
$env:APP_MODE='demo'
.\.venv\Scripts\python server.py
```

演示登录创建随机独立身份，昵称不是登录凭据；同一浏览器在会话有效期内保持身份，退出后再登录是新体验用户。演示题和奖品仅验证功能；演示红包 `demo_paid` 不发生转账。正式模式不提供演示身份接口，也不自动创建演示题库或奖品。

## 结构与运行约束

- `server.py`：HTTP API、会话、业务事务、后台任务和 SQLite 数据模型。
- `wechat_pay.py`：已开通微信现金红包商户的双向证书接口。
- `static/`：不依赖构建工具的手机端与桌面后台。
- `test_server.py`：使用独立临时数据库的 HTTP 集成测试。
- `requirements-source.txt`：提取的原始需求正文和表格。
- `data/quiz.db`：首次启动生成的运行数据，勿提交或公开。

服务默认监听本机 8080。所有业务写操作在 SQLite `BEGIN IMMEDIATE` 事务中执行；适合单实例中小规模活动。正式并发规模尚待 Q-09 确认，不能将功能测试当作生产压测。多实例扩展前需迁移到 PostgreSQL、替换本地锁与后台任务协调并开展负载测试。

## 参与流程

1. 演示体验或微信授权登录；正式用户校验公众号关注状态。
2. 首次阅读规则并确认，开始一套 5 单选＋5 多选题。
3. 单选 8 分，多选 12 分，多选全部正确才得分。每题限时 2 分钟，超时自动进入下一题；未作答不得分，整卷最多 20 分钟。答题进度自动保存。
4. 达到配置阈值可参与六格转盘抽奖；未达标可按运营配置解锁当日复活机会。
5. 中奖后查看红包状态或登记实物收货信息；活动结束后查看固定排行榜及评优奖品。

答题提交后扣减机会。计时结束服务端自动交卷，未作答不得分；每题倒计时结束自动跳到下一题，最后一题超时自动交卷；不设额外的恢复有效期。每题窗口按整卷限时平均分配（当前 1200 秒÷10 题＝每题 120 秒），不能返回已跳过的题目。服务端另有整卷 20 分钟硬上限，并在交卷时按已保存答案判分。每套题保存开始时的判分和积分规则，运营修改不会追溯更改成绩。去重窗口内题目不足时拒绝组卷并保留机会，不悄悄重复出题。服务端使用 UTC+8 自然日。活动结束后拒绝新提交，并固定榜单；首次结束后的任务或请求将快照持久化，通常在 2 秒内完成。排名依次比较积分、总用时、首次达标时间、最后答题时间，完全相同并列，第50名并列可能产生超过50个获奖者。

抽奖有单套唯一流水。权重命中不可投放奖项时为未中奖；若所有真实奖项均耗尽，则不产生抽奖流水、保留抽奖机会。预算包含实物单价预占，支付失败仍占预算，避免重试时超发。评优奖品成本需由主办方另行核定；当前抽奖预算不自动覆盖评优预算。后台导出会保留订单发放状态便于对账。

## 管理使用

后台提供概览、活动配置、题库、奖品、答题记录和发奖记录。先下载 Excel 模板，填入正式题库后导入；单次导入全量验证通过才入库，重复题、空选项、错误答案均报具体行号。演示题可逐条停用，正式环境建议使用全新数据库导入正式题库。

发货流程：`pending → shipped → received`，退回 `shipped → returned`，退回后可重新登记/发货。没有收货信息不能登记已发。现金红包不允许由管理员直接改成到账；失败初次尝试后自动再重试3次，进入 `held` 后管理员可补发。导出支持日期筛选，记录支持 openid、订单号、手机号查询。导出为 XLSX，含答题汇总及可供发货的联系信息，限制在管理员会话内。

## 正式上线配置

文档 Q-01～Q-13 中尚未确认的参数保留为后台确认项，已确认项写入配置。当前演示配置：活动名称“呼伦贝尔市深化扫黑除恶专项斗争有奖答题活动”，7 个自然日、每日免费 1 次、每日复活 1 次、每题 2 分钟（整卷 20 分钟）、取单套最高分（80 分及以上）转为积分、抽奖积分累加，多套不累计，同分按用时等规则并列同奖、主办单位为中共呼伦贝尔市委政法委员会；抽奖为六类：谢谢惠顾、积分 +10、积分 +20、现金红包 0.5 元、现金红包 1 元、现金红包 2 元；红包总额预算 25,000 元、每日 3,600 元，评优采购预算不超过 10,000 元、总预算 35,000 元。Q-08 正式题库仍在修改、Q-09 参与规模无法预估，因此生产发布开关保持关闭。正式运行前须补齐题库、完成容量评估和微信/支付联调。

以 `.env.example` 为参考配置**进程环境变量**，本项目不自动加载该文件。必须使用独立正式数据库，设置：

```text
APP_MODE=production
ADMIN_PASSWORD=至少16字符的随机强密码
PUBLIC_URL=https://正式活动域名
WECHAT_APP_ID=公众号AppID
WECHAT_APP_SECRET=公众号AppSecret
DATABASE_PATH=/data/quiz.db
```

配置公众号网页授权域名及 JS 接口安全域名、服务器 IP 白名单。OAuth 回调为 `https://正式活动域名/api/auth/callback`。网页以 `snsapi_base` 获取 openid，不强制索取头像昵称。公众号账号必须具备读取关注状态的接口权限。配置 `followUrl` 指向正式关注引导文章，`shareUrl` 指向宣传推文；关注后通过页面重新校验或授权回流。

服务生产模式要求 HTTPS 外部地址；应由 Nginx/Caddy 等反向代理终结 TLS，限制请求体5MB、连接数和访问频率，内部只开放本机服务端口。`PUBLIC_URL` 必须与浏览器 Origin 完全一致（不带尾斜杠）。生产 cookie 使用 Secure/HttpOnly/SameSite。不要将源码目录、数据库、证书目录作为网站静态目录。

### 红包方式一：已开通微信现金红包产品

设置 `PAYMENT_PROVIDER=wechat_redpack`，配置 `WECHAT_MCH_ID`、`WECHAT_PAY_KEY`（V2 API密钥）、`WECHAT_CERT_PATH`、`WECHAT_KEY_PATH`、`WECHAT_CLIENT_IP` 以及公众号 AppID。可设置发送名称、活动名称、祝福语。证书仅通过安全挂载提供，不放进代码仓库。

该适配使用微信普通现金红包接口，并以固定商户订单号先查询再发放。商户须实际开通该产品且满足微信产品额度/场景限制；不能仅填一个商户号便视为可用。状态 `sent` 是已发送待用户领取，`paid` 才是确认已领取；后台每60秒查询已发送订单。`payment_returned` 表示微信退回/失败，需要商户平台核实，系统不将退回订单自动换新单号发放。普通红包不保证无需领取的即时到账；如活动必须采用当前商家转账产品，应使用方式二连接已经核准场景的商户支付服务。

### 红包方式二：商户支付服务网关

设置 `PAYMENT_PROVIDER=gateway`、`PAYMENT_GATEWAY_URL=https://支付服务地址`、`PAYMENT_GATEWAY_SECRET`。

POST JSON：`{orderId, openid, amountCents, description}`。请求头含 `Idempotency-Key: orderId`、`X-Timestamp` 和 `X-Signature`。签名为 HMAC-SHA256(secret, timestamp + '.' + 原始请求体UTF8字节)。网关必须校验时间窗口与签名，按 `orderId` 唯一记账，并在不确定结果时查询原商户单，不得重复付款。仅返回 `{status:"paid", transactionId:"真实支付流水"}` 才被记为到账；其他响应进入重试/挂账。此方式的网关由主办方商户系统提供，本项目没有伪装为已经取得其凭据或联通。

无论采用哪种方式，上线前必须使用正式公众号、真实商户和测试参与者完成小额支付、查询、超时重试、重复点击的联调。当前交付中的自动化测试使用模拟支付响应，不证明真实商户到账。

## Docker 部署

```sh
docker build -t hulunbuir-quiz .
docker run -d --name hulunbuir-quiz --restart unless-stopped \
  --env-file /secure/quiz.env \
  -p 127.0.0.1:8080:8080 -v quiz-data:/data \
  hulunbuir-quiz
```

如使用现金红包适配，额外挂载只读商户证书，并保证容器用户有读取权限。服务只运行一个实例。Docker镜像安装依赖需要网络；本次未在此电脑构建Docker镜像。

## 验证与备份

运行 `python -m unittest -v test_server`。测试在临时数据库中进行，不改实际活动数据。

SQLite采用WAL；在线备份应使用 `sqlite3.Connection.backup()`，不要只复制活动中的主数据库文件。维护窗口停服后可整体备份数据目录。恢复前先做演练，保留原备份，且不要在已有现金发放的环境随意恢复到旧订单状态；必须与商户流水对账。当前数据含手机号和收货地址，主办方应控制后台账号、导出文件权限和保留周期。

## 交付边界

代码与本地演示可运行。正式活动起止、预算、正式题库、主办文案、外网域名、公众号/商户凭据以及真实规模验收仍需主办方提供；未进行外网部署或真实资金支付。部署前应完成真实微信手机端验收、支付联调、业务确认和按预计参与人数的压力测试。

## 微信与支付配置

公众号 AppID、AppSecret、微信商户号、商户 API 密钥、证书路径和支付模式可在后台 **微信配置** 页维护，保存后立即生效；环境变量仍可作为兜底。AppSecret 和商户密钥不会在后台页面回显，留空表示保持原值。生产环境建议限制后台访问并定期轮换密钥。

## 微信分享

微信内打开活动页时，前端会通过 JS-SDK 配置“发送给朋友 / 分享到朋友圈”的标题、描述、链接和封面图。需要在公众号后台配置 JS 接口安全域名；分享入口使用微信右上角菜单，网页内不另设分享按钮。

## 用户管理

后台提供只读用户列表，可查看昵称、头像、关注状态、账号类型、答题次数、最高分、中奖订单和注册时间；当前不提供编辑、封禁或删除操作。

## 复用给其他单位

- 活动配置可改：活动名称、主办单位、品牌副标题、分享描述、活动时间、答题/复活/榜单规则、预算、奖品说明。
- 题库和奖品在后台维护，支持 Excel 导入题库。
- 微信配置可改：公众号 AppID/AppSecret、商户号、APIv3 密钥、商户证书、转账场景、红包样式。
- 服务器域名通过 `PUBLIC_URL` 配置；更换部署环境时改环境变量并重新签发证书。
- 后台“重置活动数据”可清空用户/答题/抽奖/订单与封榜状态，保留题库、奖品、活动配置和微信配置，便于下一单位复用。
- 后台“个性主题”提供 3 套模板（深蓝政务 / 红金庆典 / 清新青蓝），可配置主题色取色器、首页背景上传、活动规则正文及 32 项页面文案。
- 主题色、首页背景图、活动规则正文、首页主要文案、页脚、登录/结果提示均可在后台配置；规则正文填写后会替换默认规则。
- 仍有少量结果页主标题和动态提示固定在代码中，可按需要继续扩展。

## 页面文案配置

活动配置中的“页面文案”提供 32 个字段，覆盖登录、答题、单/多选提示、结果页、抽奖、排行榜、获奖公示和我的奖品的主要固定文案；留空使用默认值。规则正文填写后会替换默认规则。
